# 開発メモ（Claude との作業記録）

## プロジェクト概要

### 2026-10-03 新アプリの管理設定・変更履歴を折り畳みなしに整理

- 管理設定は「現在の管理状況」と目的別4カード（終了・再開、今後の予定追加、振替1件追加、保存済み予定変更）に分離。入力は共通Modalで開き、画面の折り畳み/入れ子/フォーム常時展開を撤去。既存エディターにexpanded表示を追加し、元の保存・確認・請求回ID/版・契約スナップショット/RPCは変更しない。
- 新ラッパーは保存中の閉じる操作を止め、確認できた保存成功時だけ閉じて結果を表示する。失敗/結果不明時は例外を元エディターへ戻し、入力・確認結果を維持。ランタイム更新時のエディターの版リセット用keyを維持。
- 変更履歴は記録日時順の一覧と種類別フィルター（所有者変更/請求の変更/終了・再開）に変更。管理の終了・再開履歴もこちらへ移動。適用日と記録日を分け、同日の時刻は日本時間で表示。記録日時未保存の旧/合成記録のみ適用日を明示したフォールバック。
- 詳細は読み取り専用Modalの変更前/変更後表。変更した業務項目を先に表示し、全保存項目も切り替え可能。未知の項目を落とさず、保存済み契約55項目の参照を維持。金額は保存値のみ、0円/未記入を区別し、現在の契約による再計算はしない。差分をDBへ二重保存しない。
- `management-history-layout.cjs` でSSR、保存失敗/不明時の画面維持、保存中閉じない、実コールバックの引数維持、種類フィルター、時系列、完全スナップショット/未知項目を検証。合成データ限定 `management-history-preview.html` で通常保存/失敗/履歴詳細を確認。DB・旧アプリ・移行データの変更なし。

### 2026-10-03 新アプリの顧客選択を検索式に変更

- 共通 `CustomerPicker` を所有者変更、発電所新規作成の既存顧客、請求先の予定編集・訂正・1回追加・振替追加・今後の予定設定に適用。既に検索式の見込み管理は変更しない。会社名・個人名・登録ふりがなの部分一致、空白/全半角/かな差を吸収。別漢字の推測置換は行わない。
- 入力中は選択中の会社名・個人名・顧客IDを明示して維持し、候補の明示選択でのみIDを切り替える。候補は件数付きスクロールで全件表示、キーボード選択/IME確定/該当なし/解除にも対応。全顧客を再取得する通信や顧客自動作成はない。
- 所有者変更では現所有者を除外。各回の旧/新/元請求先制限、振替不能時の固定、busy fieldset、既存保存バリデーション/確認無効化/原子RPCを維持。Appの請求先候補には会社名・ふりがなを含む既存Customerオブジェクトを渡す。
- 検索専用テストと請求先変更時の再確認テストを追加。合成データだけの `customer-picker-preview.html` はDEV+rehearsal限定。検索30件目選択と実InvoicePlanEditorの回ID/版/予定額を維持した顧客ID保存を隔離ブラウザーで確認。実DB・旧アプリ・移行データの変更はない。

### 2026-10-03 新アプリの請求一覧を旧UIに合わせて整理

- 請求タブ専用の `BillingOverviewTable` に分離。未入金を先頭、今月〜再来月の請求予定を次に表示し、発電所横断で1回1行・日付順。保存済み予定と未保存候補は同じ表で、請求先候補/参考額/未保存は明示する。表示件数制限なし。
- 「請求履歴」と4集計欄の繰り返しを廃止。「入金済」「口座振替」「設定要確認」等は件数付き折り畳み。古い未入金・金額不明の警告は初期表示に残す。
- 一覧の保存済み回から既存の発行・入金・振替・請求先フォームを共通Modalで開く。Appの既存 `saveRuntime(action:invoice)` に接続し、回ID・版・認証・再試行・原子更新は詳細と同じ。未保存候補を自動発行・追加しない。
- 常時の振替発電所一覧を復帰。現契約の今月参考額のみ表示、保存済みの各回の金額/請求先とは混同しない。全管理終了を除外し、保守終了後は保守料を参考額から除外。結果確認対象の判定は変更しない。
- 請求詳細の期間グループ、既存CSV、DB/RPC、旧アプリ、実データは変更しない。旧→新の最新データ同期は別作業。
- `test:ui-layout` に `billing-overview-layout.cjs` を追加。24候補の全件表示、保存済みとの日付順、請求先/0円/不明額、古い未入金の継続、初期折り畳み、回ID別のフォーム接続を検証。`billing-overview-preview.html` はDEV+rehearsalかつ合成データ/メモリー更新のみ。

### 2026-10-03 新アプリの請求詳細・日常導線と期間別表示

- `InvoiceLedgerDetail` に契約からの未保存参考候補を追加。実績と区別し、確定額・保存済み予定額は従来の `resolveUnitAmount` のまま。契約を変更しても保存済み各回の金額は再計算しない。
- `BillingOccurrenceCreator` → App の `future_schedule` →既存 `billing_runtime_write/create_future_schedule` で確認した1回のみ追加。既存の契約スナップショット、全回の版、管理履歴の最終ID、理由、冪等性、トランザクションを利用。DBスキーマ/RPC/移行データは変更しない。追加後、選択した回の通常発行・振替結果フォームに接続。
- `billingDetailPeriods` は保存済みの開始/終了を優先し、未保存のみ保守開始日と serviceYear から参考表示。同じ期間の複数回を一つの枠内に表示。請求日・入金日による年/回/期間の付け替えは行わない。例外期間、部分欠損、開始日欠損は推測で確定しない。
- 期間/回/日付の変更時は元候補の予定額をクリアし、再確認を要求。旧月単位/回数未確認記録、取りやめ済みの回は既存RPCと同じ対応確認境界で保護。開始日未設定は金額を参考表示するが、拒否される通常保存ボタンは出さない。
- 合成データ専用 `billing-detail-period-preview.html` は DEV + rehearsal のみ動作。通常ビルドでは起動しない。実DBへの接続・認証・外部保存はない。
- `tests/billing-detail-periods.cjs` は期間内2回、前払い、保存済み例外、未確認/欠損/閏日、請求対象外保守料、予定と実額分離、重複/終了/重なり、実フォームの確認と再確認・0円・1回だけの送信を検証。実画面で合成振替の予定追加→結果記録と、同一期間第2回の発行後に第1回が残ることを確認。

上記は新アプリのみ。旧DB差分の同期、既存記録の保守期間確定、実データの請求/入金記録追加はこのUI変更では行わない。

## データベース

### schema.sql の修正

`database/schema.sql` を実際のアプリコードに合わせて全面書き直し済み。

#### テーブル一覧（8テーブル）

| テーブル名 | 説明 |
|---|---|
| `customers` | 顧客（個人名・法人名） |
| `projects` | 案件（発電所情報・パネル・PCS・監視等） |
| `contracts` | 契約情報（1案件につき1件） |
| `annual_records` | 年次請求記録（`UNIQUE(contract_id, year)`） |
| `maintenance_responses` | 保守対応履歴 |
| `periodic_maintenance` | 定期点検記録 |
| `attachments` | 添付ファイル（Supabase Storage 連携） |
| `prospects` | 見込み客 |

#### annual_records の重要仕様
- `year` フィールドで年ごとにレコードが分かれる
- 入金完了にしても翌年は新しいレコードが作られるため履歴として残る
- `status`: `'未入金' | '請求済' | '入金済'`
- `line_items`: JSONB `[{name, amount}]` 形式

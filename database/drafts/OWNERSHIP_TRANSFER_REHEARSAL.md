# 所有者変更の一括保存・隔離検証

最新拡張：請求方法・回数・予定日を維持した金額／手数料フラグ／請求対象／回別上書き変更を追加検証。予定日の形式、回数との一致、対象外の回キー、非負整数・計算上限、発行手数料の必須額を検証する。方式・回数・予定日自体の変更はまだ拒否する。2月29日のような年度依存の予定を実際の年へ展開する検証は予定生成側で必要。税込・税抜を自動換算する変更はしていない。

`20260907_transfer_ownership_inherit_rpc.sql`は、foundation・invoice_write_rpc・invoice_recipient_plan_rpc・transfer_detail_choicesの後に適用する。明示トランザクションとdraft設定が必要。PUBLIC実行不可・SECURITY INVOKER・auth.uid必須。通常アプリ未接続・本番未適用。

最新拡張：末尾の任意引数p_field_choicesで、購入日・購入額・販売経路・各備考等の限定された変更／空欄化に対応。省略は全保持。関数名のinheritは既定動作を示し、変更を全て拒否する意味ではない。旧11引数の既適用環境に上書きする本番マイグレーションではなく、隔離DBへ最初から適用するドラフト。

## できること

- 契約内容をそのまま引き継ぐ請求書払いを対象に、現所有者・旧所有者・所有権移転日を更新する。
- 今後の請求先の既定と回別例外を既存RPCで保存する。次回A／その次Bと、次回からすべてBの両方に対応。
- project、現請求先指定、契約、請求回をロックし、確認時のproject／contract全JSON・現指定の版・全planned回の版を再照合する。
- 契約・発電所の変更前後全JSON、D-026 inherit_allの選択方針、システム更新した3キー、確認結果、日時・実行者・A/BのIDを移転履歴に保存。
- 親の移転操作と子の請求先指定操作は同じトランザクション内。最後の移転履歴INSERTが失敗しても、先行した所有者・契約・請求先・両操作記録を全て戻す。
- A→B→Cと進んでも過去の移転履歴は不変。過去の操作を再送しても旧所有者へ巻き戻さない。返り値は移転ID等の受付だけで、機微情報の全JSONを返さない。
- RPC自身は既存actionsのsyncBackToProspectを呼ばず、prospectsを更新しない。

## 検証

`npm run test:billing-db`へ統合。PGliteの架空データで全体保存・終端失敗時の全取消、A→B→C、次回例外・次回から新所有者、全JSON保持、過去入金の全値保持、見込み不変、古い確認拒否、同一所有者・未来日・過去の移転より前の日付・未認証・誤再送・未移行記録の拒否を確認。

## 限定範囲と残件

1. **旧annual_recordsが1件でもある対象契約は拒否する。** 移行済みを意味するフラグで回避できる実装ではない。実際の移行完了を原本ハッシュ・回数・履歴・金額等で照合する処理へ接続した後、この暫定ゲートを置き換える。既存記録を削除して回避してはいけない。
2. **個別変更は限定した項目だけ接続済み。** 購入関連日・購入金額・販売経路・会員番号・備考等と、構成を維持した保守料等の金額変更は、サーバー側で明示許可したキーだけ更新する。数値・日付・文字列、選択の必須キー、システム項目禁止、旧設備契約日フォールバックを検証。billing_method・回数・予定日等の構成変更は追加検証まで拒否する。その他の未接続項目も勝手に保存しない。
3. 振替・将来日予約・過去の移転の訂正・未発行予定がない発電所は未対応。今回の制限をユーザーが恒久的に承認した業務仕様と扱わない。
4. 既存データの請求金額をこのRPCで固定する処理は追加していない。新billing_unitsの確定済み状態のDB制約と、旧データの暫定拒否に依存する。
5. 実DBのトリガー・RLS・参照元への逆同期の監査、権限、プロジェクトロックを守らない旧更新経路の封鎖、複数接続競合・永続復旧試験は残る。fixtureで見込みが不変でも本番トリガーの安全性を証明しない。
6. 全JSONスナップショットには監視情報等の機微情報が含まれ得る。権限制御なしに履歴全体を通常画面やログへ露出しない。差分の二重保存・過去金額の再計算には使わない。

本番の所有者変更機能が完成したわけではなく、基本ケースの原子的保存を隔離環境で検証した段階。

## 個別選択の保存

- 変更対象はサーバー許可リストと元行に存在する項目の共通部分。SQL列名は許可済みキーを引用し、値はパラメータ経由で渡す。任意after JSONを全列更新に使わない。
- 既定保持と明示選択は移転履歴のfield_decisionsへ、実際の旧値・新値は全JSONスナップショットへ残す。失敗時は選択項目の更新も所有者・請求先と一緒に戻す。
- 金額変更のうち対応するのは設備代などの購入金額であり、毎回の請求金額ではない。過去請求の固定額は変えない。
- 型にあってもDB側にないoptional項目は選択を拒否する。全実DB列の対応確認、UIの選択可能項目との同期、未接続キーの表示制御は残る。

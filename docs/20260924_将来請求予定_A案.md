# 将来の請求予定：A案を採用（2026-09-24）

利用者は、将来の全回を先にDBへ一括登録するB案、請求書だけ先に登録するC案ではなく、A案を選択した。これは**保存時点の方針**であり、新アプリの本番公開承認ではない。

## 業務上の意味

- 現契約の「請求予定日」から将来の候補を画面に出す。未保存候補は発行・入金・振替成功を意味せず、表示額も契約からの参考額とする。
- 請求書は、対象回の請求先・方法・予定日・金額を人が確認してから回別記録に保存する。発行時の実額は別途凍結する。確認前に全将来回を一括作成しない。
- 所有者変更時に「次回はA、その次からB」など利用者が明示した請求先の指定は、候補表示とは別に永続化し、次回表示で失わない。未保存候補のまま自動的に現所有者へ確定しない。
- 口座振替は銀行が実行する。このアプリは当月の確認日を表示し、実際の結果を見てから記録する。月ごとの記録は必要時に作るが、24か月分を未払い・振替成功として先に登録しない。
- 全取引終了、保守だけ終了、再開、方法変更、日付変更、既存の発行済み・入金済み記録は別々に扱う。既存実績の金額・請求先を将来候補で上書きしない。

## 2026-09-24の実データ照合

- 87発電所中、設定から候補を出せるのは請求書16・口座振替15発電所。向こう24か月の暦日候補398件＝請求書38回＋口座振替360か月分。
- 新DBに保存済みの請求回は32件。請求書38回のうち37回、口座振替360か月分が未保存。未保存は未払いの意味ではない。
- 設定要確認56発電所は、請求設定が必要26件と自社請求なし候補30件に分けて表示し、勝手に設定しない。
- 現データで候補が期日に画面から見えなくなる例は0件だった。ただし24か月の現データだけで将来の契約変更・所有者変更まで保証しない。

## 実装・公開の境界

- 隔離コピーの通常「請求」・「ダッシュボード」では、今月～再来月の未保存請求書候補を保存済み予定と同じ見出しの下に区別して表示し、同日の保存済み回は二重に数えない。口座振替の確認は別見出しにする。
- 隔離コピーの所有者変更画面では、既存予定とは別に「まだ保存していない1回」を明示入力できる。対象保守期間・第何回・方法・日付・請求先・税込予定額を確認した場合のみ、所有者変更と同じDBトランザクションで保存する。既定先Bに対してその1回だけAを選べる。重複、旧契約・旧予定の更新、監査記録の失敗時は全部取り消す。4通りの請求書／口座振替の組合せ、再送、失敗時復旧を隔離Postgresで試験済み。DB差分 `database/drafts/20260924_transfer_selected_next.sql` は新DB `ufawaiddntqqbjhycbxn` に適用済み。適用後もランタイム0行、発電所87件・請求回32件・金額合計不変。旧DBには未適用。
- その回が通常の契約予定日と一致する場合は、保存済みのA宛て回を現所有者Bとの不一致として誤警告しない。保存した日付を契約の標準日から変えた場合、近接する同じ回の保存記録があれば「別日に保存された同じ回の可能性」として要確認にし、新規の請求候補と断言しない。300日を超える変更や保守期間が特別な案件では自動対応付けをせず、候補を残して人が確認する。現行のランタイム読取RPCは請求先プランを返さないため、未保存候補の「現在の顧客」を確定請求先として扱わない。
- 期限切れ・保存内容不一致の候補は隠さず、要確認として残す。候補を見せるだけで保存・発行・振替操作を行わない。
- 新DBの通常請求ランタイムは引き続き無効。表示テストだけで `future_schedule_coverage_verified` を真にしない。所有者変更・日付変更・管理終了／再開を含む受入試験、権限、切替・切戻しを確認後に別途公開判断する。
- 旧アプリ・旧DBはこの決定とローカル画面変更では無変更。

# 顧客・請求詳細の履歴表示準備

BillingHistorySectionを既存CustomerDetailView/BillingDetailViewへ任意billingHistory入力として接続。保存請求先による横断抽出、発電所名ごとの表、確定額集計、未知金額の別表示。認可済みデータを呼出元が渡す前提で、現所有者から請求先を補完しない。

BillingDetailで新入力を指定すると読取専用となり旧年度の編集欄は表示しない。通常Appからの取得・指定はまだなく、旧画面は従来動作を維持する。CustomerDetailの請求以外の操作は従来どおり。

DEV専用billing-history-preview.htmlは架空データのみ。同一部品で顧客A/B別と発電所別表示を比較できる。ブラウザで現在Bでも顧客Aの過去82,500円が残り、発電所の表にA過去/B予定が並ぶことを確認。既存Detail全体の操作テストではない。

残る：認可されたDB横断取得/行変換、RPC保存と再読込、通常請求/ダッシュボード集計、実データ切替・振替・権限/復元検証。公開・本番適用なし。
# 追加：DB保存行の厳密変換

billing-unit-storage.tsで実SQL行のID/年度/月/回/日付/方法/状態/請求先/確定額・明細・時刻を検査しBillingUnitへ変換。現在所有者・現契約の補完なし。単回の不明回番号を第1回と捏造せず「保存済み単回記録」と表示。実移行SQL出力で値一致と不正値拒否をテスト。

invoice-db-previewのreloadで変換し、BillingHistorySectionへ渡す。既存の発行/入金/訂正後の再読込経路でも更新される。予定額の計算根拠がないため検証画面の履歴部品はnullを渡す。通常AppのSupabase取得・権限・切替は未接続。変換はDB制約の代替ではなく、全不正状態の検証器でもない。
# 追加：一覧・ダッシュボード用の分類集計

billing-overview.ts追加。ローカル日付を明示入力し、今月～再来月（年越し対応）の未発行請求書予定、今年/昨年度の未入金/入金済を保存値から分類する。予定revision変更だけでは消えず、発行で未入金へ。現所有者/契約から額や先を補わず未知額を別計数。期限前の旧予定/日付なし/将来予定/振替予定/要確認も別配列で保持する。cancelledは通常請求対象にしない。

BillingOverviewPanelを架空billing-history-previewへ追加。通常Billing/Dashboardの既存取得経路・操作はまだ未切替であり、新パネルは検証用。年越し/保存済み予定/発行/入金/来年6月/未設定/取消の純粋試験追加。本番未変更。
# 追加：一覧・ダッシュボード本体へ明示入力接続

BillingにbillingHistory/billingToday任意propを追加。新入力ありならLegacyBillingをマウントせず読取専用共通パネルへ。新入力なしは従来経路。Dashboardも同入力で請求計算と旧請求表を切替え、顧客数/案件数/保守カードと対応中保守表は保持。新入力時は旧computeUnpaidUnits/computeUpcomingInvoicesを呼ばず、未入金KPIも新集計を使用。振替旧推測アラートを混在させない（新振替確定運用は未対応）。日付はUTC変換ではなくローカル年月日。

DEV履歴ページで両View本体を架空入力からレンダリング。ブラウザで一覧/ダッシュボードの同じB予定1件、非請求KPIと保守表保持を確認。2027年基準の今年/昨年度集計から2025実績が外れる一方、顧客履歴には残る。通常Appは新入力をまだ渡さず本番取得/切替なし。新経路は読取のみ、詳細遷移/発行/入金RPC操作は未接続。
# 追加：発電所別詳細への遷移

共通履歴の発電所見出しに任意onViewDetail付き「請求詳細を開く」を追加。Billingの既存onViewDetail、DashboardのonViewBillingへ接続。DEVページは選択projectの読取履歴と「一覧に戻る」へ遷移する。通常Appの新データ取得は依然未接続。

期間前/日付なし/それ以降/振替/要確認の件数だけだった分類をdetailsで展開し、対象の回と詳細ボタンを確認可能にした。通常3か月の範囲は変えない。DEV遷移は共通履歴部品でありBillingDetail全体の保存操作には未接続。クリック往復の自動ブラウザ検証はまだ。
# 追加：保存と再読み込みの再試行管理

invoice-write-session.ts追加。操作ID/対象回/版/入力の値コピーを1編集セッションで保持し、書込→reload完了まで同じIDを再利用。結果不明中の別入力は拒否。DBが明確に取消したエラーだけは依存側判定でpending解除し修正可能にする。invoice-db-previewの直接randomUUID呼出をこの処理へ置換。

入力拒否と保存成功後reload失敗を分離する試験追加。本番アダプタはまだなく、判定は隔離PGliteの限定SQLSTATEのみ。ページを閉じた後の永続的な再試行、通常BillingDetailの編集フォーム接続は未対応。操作IDだけでネットワーク結果を推測しない。

# 電力会社契約書PDFの読み取り（2026-10-31）

対象は電力会社全般。提供された2社を先行テストとして実装し、書式を順次追加する。画面の固定案内は会社名を列挙せず「電力会社の契約書」に統一。未対応書式を読み取れない場合は、追加対応が必要と案内する。

新アプリ専用。基本情報の「電力会社」からPDFを選び、現在値と読み取り値を比較する。初期状態では全項目未選択。反映する項目と確認欄にチェックして保存する。ファイル名に依存せず文面で2社の指定書式を識別する。

## 転記の仕様

- 共通：認定ID→設備ID、受電地点特定番号→受給地点番号。
- 関西：認定日・受給開始日を対応欄へ。特定契約日（受給契約日）→電力変更日。税別買取単価→FIT。FIT期間は受給開始日の20年後の翌月（2019-12-20→2040年1月）。年月はDBに月初日で保存する。
- 九州：受給開始日→電力変更日。受給開始日欄・認定日は変更しない。固定買取終了年月→FIT期間。税込購入料金単価をユーザー指定の1.1で割りFITへ転記。端数を丸めない。既存FIT列は整数のため、小数が残る単価は選択を外して確認する。
- 発電場所・最大受電電力・読めた電気方式、周波数、電圧・電力会社連絡先は電力会社備考へ追記。既存備考は保持する。顧客側の連絡責任者・電話と混同しない。パネル出力・概要住所・顧客・所有者は変更しない。
- 画像の名義や文字には誤読がある。照合用に表示し、空欄や不足は元PDFを見ながら修正する。自動承認・自動保存は行わない。

## 処理と保存

文字PDFはPDF.js、画像PDFは日本語OCRをブラウザーのWorkerで読む。PDF自体は外部APIやStorageへ送信しない。言語データとWASMは同一オリジンから選択時だけ読み込む。15MB・10ページ・画像3ページ・120秒の制限。終了・中止・失敗時にWorkerとCanvasを破棄する。

専用RPC power_contract_applyはSECURITY INVOKER。利用者チェック、行ロック、選択項目の変更前比較、所有者・保管状態の再確認、日付・単価の検証を行う。選ばれていない項目は現在値を保持。同一リクエストの再送で重複追記しない。請求・契約・保守・顧客テーブルを更新しない。移行SQLは既存行を変更しない。

## 検証

npm run test:power-contractで合成書類・Worker中断・DB保護を検証する。提供された2社の実物PDFは隔離画面で照合し、本番発電所へ保存しない。PCと390px幅、未選択時の保存禁止、不正単価エラー、選択保存、中止後のWorker終了を確認する。旧認定書・請求の回帰テストも実施する。公開先・公開確認の証拠は社内00台帳の最新記録を参照。

実物PDF・抽出結果・認証情報はリポジトリや共有資料に含めない。

## 読み込み画面を閉じる際の確認

読み取り内容の手直し、項目選択、確認チェック、保存結果未確認のいずれかが残る場合は、フッター・X・背景・Escで閉じる前に確認を表示する。「編集を続ける」で元の値・選択・フォーカス・スクロール位置を保持する。確認中のEsc・背景・Xも編集復帰とし、明示的な「保存せずに閉じる」でのみ破棄する。保存結果未確認の場合は保存済みの可能性を明記し、同じリクエストで再確認できる状態を保つ。保存中は閉じられず、保存成功後は直接終了する。読み取りだけで未修正・未選択の場合の終了は従来どおり。共通Modal、DB、読み取り判定は変更しない。ページ再読込・別PDFへの差し替えは今回の閉じる確認の対象外。

## 追加スキャン書式の修正（2026-10-31）

- 原因：PDF.js 6がCCITT/JBIG2の画像を描画する際のWASM配置・URLが不足し、文字の層が白紙になっていた。約101KBのデコーダーと非WASMフォールバックを同一オリジンで配信し、PDF選択後のみ読み込む。
- 九州の3列形式で、疎な文字向けOCRが表を落とす場合にブロック向けOCRを1回追加。同じ会社・契約タイトル・表の見出しが揃った結果だけ採用し、複数パスを混在させない。
- 設備IDは既存の2英字始まりに加え、1英字＋6数字の形式にも対応。全値一致とし、長い誤読文字列の一部をIDとして採用しない。
- 提供された画像PDFを隔離した実アプリ画面で検証：設備ID・受給地点番号・電力変更日・税抜FIT・FIT期間の5項目を抽出。個人名・住所・契約番号などの実例は共有資料やリポジトリへ格納していない。
- OCRは完全ではなく、備考の電話番号の誤読や周波数の取りこぼしがある。元PDFとの照合・手直し・明示的な項目選択を継続する。
- 保存RPC・DB・請求・顧客・所有者・保守の記録は変更していない。既存の閉じる確認・中断・120秒上限も維持する。

## 関西の画像契約書の精度改善（2026-10-31）

- 罫線をまたぐ全ページOCRでID・日付・地点番号が欠落する画像書式に対応。実画素から検出した罫線セルを使い、座標をテンプレートで決めつけない。単純な表を検出できなければ従来の読み取りへ戻る。
- 関西契約書の主要7項目が初回で揃った場合は追加のセルOCRをしない。不足がある場合に限って見出しを再利用し、日付は不足項目のみ補正、ID・地点番号は英数字モデルで検証する。英数字の欠損や余分な桁を補ったり切り捨てたりしない。
- 再読値が不正なら初回結果を維持。有効な既存日付・単価、名義・住所には再読による置換をしない。認定日と受給開始日・契約日を隣のセルから取り違えない。
- 英数字モデルは固定依存 @tesseract.js-data/eng@1.0.0 の軽量データを同一オリジンで必要時のみ取得（約3MB）。通常画面では取得しない。処理はWorkerで継続し、言語切替中の中断も検証。120秒上限と後片付けを維持。
- 追加の提供PDFを隔離実画面で原文照合し、主要7項目が一致。住所の難字の誤読などOCRの限界は残り、元PDFとの照合と手修正が必要。実物PDF・顧客固有値は共有資料やGitへ格納していない。
- 罫線検出、正常時の再読省略、不正な英数字の扱い、有効な初回日付の保持、英語モデルのロード中断、従来の読み取り・保存保護をテスト。サブエージェントの性能・品質指摘を修正後、再レビューで重大指摘なし。
- DB・保存RPC・請求・保守・顧客のデータは未変更。公開コミットと確認結果は既存の社内台帳へ記録する。

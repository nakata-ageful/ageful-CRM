# 電力会社契約書PDFの読み取り（2026-10-31）

新アプリ専用。基本情報の「電力会社」からPDFを選び、現在値と読み取り値を比較する。初期状態では全項目未選択。反映する項目と確認欄にチェックして保存する。ファイル名に依存せず文面で2社の指定書式を識別する。

## 転記の仕様

- 共通：認定ID→設備ID、受電地点特定番号→受給地点番号。
- 関西：認定日・受給開始日を対応欄へ。特定契約日（受給契約日）→電力変更日。税別買取単価→FIT。FIT期間は受給開始日の20年後の翌月（2019-12-20→2040年1月）。年月はDBに月初日で保存する。
- 九州：受給開始日→電力変更日。受給開始日欄・認定日は変更しない。固定買取終了年月→FIT期間。税込購入料金単価をユーザー指定の1.1で割りFITへ転記。端数を丸めない。既存FIT列は整数のため、小数が残る単価は選択を外して確認する。
- 発電場所・最大受電電力・読めた電気方式、周波数、電圧・電力会社連絡先は電力会社備考へ追記。既存備考は保持する。顧客側の連絡責任者・電話と混同しない。パネル出力・概要住所・顧客・所有者は変更しない。
- 画像の名義や文字には誤読がある。照合用に表示し、空欄や不足は元PDFを見ながら修正する。自動承認・自動保存は行わない。

## 処理と保存

文字PDFはPDF.js、画像PDFは日本語OCRをブラウザーのWorkerで読む。PDF自体は外部APIやStorageへ送信しない。言語データとWASMは同一オリジンから選択時だけ読み込む。15MB・10ページ・画像3ページ・120秒の制限。終了・中止・失敗時にWorkerとCanvasを破棄する。

専用RPC power_contract_applyはSECURITY INVOKER。利用者チェック、行ロック、選択項目の変更前比較、所有者・保管状態の再確認、日付・単価の検証を行う。選ばれていない項目は現在値を保持。同一リクエストの再送で重複追記しない。請求・契約・保守・顧客テーブルを更新しない。移行SQLは既存行を変更しない。

## 検証

npm run test:power-contractで合成書類・Worker中断・DB保護を検証する。提供された2社の実物PDFは隔離画面で照合し、本番発電所へ保存しない。PCと390px幅、未選択時の保存禁止、不正単価エラー、選択保存、中止後のWorker終了を確認する。旧認定書・請求の回帰テストも実施する。公開先・公開確認の証拠は社内00台帳の最新記録を参照。

実物PDF・抽出結果・認証情報はリポジトリや共有資料に含めない。
